# DotaCounters — техническая документация

Портативный десктопный инструмент для анализа контрпиков в Dota 2: tkinter,
один `.exe` без установки. Документ описывает, как устроена программа, откуда
берутся данные и какие подводные камни у источников.

Пользовательское описание — в [README.md](README.md).

---

## Общая картина

```
main.py                    только запуск окна
dotacounters/
    version.py             APP_VERSION — единственное место с номером версии
    config.py              dota_config.json и папка cache рядом с программой
    net.py                 HTTP-клиент (curl_cffi с отпечатком Chrome)
    heroes.py              список 127 героев, прозвища, подбор подсказок
    roles.py               роли героев по разметке Valve (собирается скриптом)
    dotabuff.py            загрузка и разбор страницы контрпиков
    draft.py               подбор пика против нескольких врагов
    patches.py             патч и заметки к нему из datafeed Valve
    icons.py               иконки: кеш, растеризация SVG, рисованные значки
    updates.py             проверка и установка обновлений с GitHub
    relaunch.py            перезапуск после обновления с чистым окружением
    recent.py              избранное, недавние герои, геометрия окна
    pagecache.py           кеш разобранных страниц Dotabuff на сутки
    hotkey.py              глобальная горячая клавиша (RegisterHotKey)
    themes.py              5 цветовых схем
    i18n.py                все строки интерфейса, ru/en
    ui/
        app.py             главное окно: 4 вкладки, вся логика интерфейса
        overlay.py          оверлей поверх игры: контрпики и драфт
        role_menu.py        выпадающий список ролей — во вкладке и в оверлее
        hero_browser.py     модальный список героев
        suggestions.py      выпадающие подсказки под полем ввода
        patch_notes.py      модальное окно заметок к патчу
        winapi.py           тёмный заголовок, вывод окна на передний план
tools/
    update_roles.py        пересобрать roles.py из datafeed Valve
```

Правило, которого стоит держаться: **в `ui/` нет разбора данных, а вне `ui/`
нет виджетов**. Поэтому разбор страниц, подбор в драфте, сравнение версий и
работа со списками проверяются тестами без окна и без сети.

Все сетевые запросы идут в фоновом потоке, результат возвращается в интерфейс
через `root.after(0, ...)`.

## Источники данных

| Что | Откуда | Чем неприятен |
|---|---|---|
| Контрпики | `dotabuff.com/heroes/{slug}/counters` | Cloudflare, случайные 403 |
| Патч и заметки | `dota2.com/datafeed/patchnotes*` | Схема не та, что кажется |
| Иконки | CDN Valve и Dotabuff | Часть картинок отсутствует |
| Обновления | `api.github.com/.../releases/latest` | — |

### Dotabuff: страница контрпиков

Три вещи, на которых легко ошибиться (все проверены на живой странице):

1. **Таблиц три, а не две:** «X is countered by», «X counters» и полная
   «Matchups» на 126 строк. Брать первые две по счёту — совпадение, поэтому
   разделы опознаются по заголовку над таблицей.
2. **Колонки сдвинуты:** в `<thead>` три заголовка, а в строке четыре ячейки —
   у ячейки с иконкой заголовка нет. Сопоставление «i-й заголовок = i-я ячейка»
   даёт молча неверные числа: на месте винрейта окажется преимущество. Сдвиг
   вычисляется как разница длин, колонки ищутся по тексту заголовка.
3. **Значения продублированы** в атрибуте `data-value` в машинном виде —
   именно оттуда берётся число преимущества для драфта.

Если на месте винрейта оказался не процент, разбор **бросает `ParseError`**, а
не показывает число: молча неверные данные хуже видимой ошибки. Если не
опознались заголовки разделов, происходит откат к прежнему поведению (первые
две таблицы) с пометкой `degraded`, и интерфейс предупреждает.

### Cloudflare и 403

`cloudscraper` перестал проходить в сентябре 2026: он подделывает только
заголовки, а проверяется ещё и TLS-отпечаток соединения. Используется
`curl_cffi` с `impersonate="chrome"`.

Замеры на живом сайте:

- новая сессия на каждый запрос — 403 примерно на каждом четвёртом холодном;
- **одна общая сессия — 5 запросов из 5 проходят и вдвое быстрее**;
- прогрев сессии лишним запросом не помогает;
- повтор помогает: из 12 страниц одной попытки хватило 8 раз, двух — 10,
  трёх — 11.

Отсюда два правила: `fetch_counters` повторяет запрос дважды с нарастающей
паузой (`RETRY_PAUSES`), а драфт ходит по всем врагам **одной сессией**.

### Valve datafeed: заметки к патчу

Схема не такая, какой кажется по названиям полей:

| Ожидается по наитию | На самом деле |
|---|---|
| `generic_notes` | `general_notes` |
| `heroes` — словарь по именам | **список** `[{hero_id, hero_notes, abilities, talent_notes, subsections}]` |
| `items`, `abilities` — словари | **списки** |

Имён в ответе нет — только числовые идентификаторы; они разрешаются через
`herolist` / `itemlist` / `abilitylist` и кэшируются на язык.

Дополнительно разбираются: `talent_notes` (таланты), `neutral_creeps`,
поле `info` (пояснение под заметкой), флаг `aghanims` (скипетр или осколок) и
`title` (пометки «New Item», «Item Reworked»). Раздел `subsections` — это
аспекты героев; они убраны из игры в 7.41, и раздел **сознательно
пропускается**.

Язык передаётся в каждый запрос. Текст заметок и названия способностей Valve
переводит, а **имена героев и предметов — нет, ни на одном языке**, как и в
самой игре.

## Ключевые алгоритмы

### Подбор в драфте (`draft.py`)

На странице героя в таблице «Matchups» для каждого соперника указано,
**насколько хуже этот герой играет против него**. Значит, чтобы выбрать пик
против состава, достаточно сложить эти числа по всем врагам: чем больше сумма,
тем неудобнее кандидату противостоят.

Тонкости:

- кандидат учитывается, только если встретился **у всех** учтённых врагов,
  иначе сумма по одному врагу конкурировала бы с суммой по трём;
- герои, уже взятые противником, из кандидатов исключаются, как и союзники
  с банами (`exclude`);
- фильтр по роли (`role`) применяется к обоим спискам — «брать» и «не брать»;
- враг, чью страницу не удалось загрузить, попадает в `skipped`, называется в
  выводе и **не участвует** в сумме; в заголовке перечислены только учтённые.

Проверка направления, которая стоит всех остальных: при одном враге результат
обязан совпасть с таблицей контрпиков с его же страницы — на этом есть тест.

**Состав** (`DraftBoard`) — враги, союзники и баны плюс скачанные страницы
врагов. Он один на вкладку «Драфт» и оверлей: героя, добавленного в одном
месте, видно в другом, а страница врага качается один раз. Сеть качает главное
окно (`_fetch_enemies`, одна сессия под замком), оверлей только сообщает об
изменении состава. Один герой не бывает сразу в двух списках: добавление в
другой список переносит его. Не загрузившаяся страница сама не повторяется —
только по кнопке «Подобрать», иначе каждое изменение состава снова стучалось бы
в отказавший Dotabuff.

**Роли** — `role_levels` из `datafeed/herodata`: уровень 0–3 для девяти
ролей Valve (carry, support, nuker, disabler, jungler, durable, escape, pusher,
initiator). Позиций «мид» или «4» у Valve нет, фильтр — по этим ролям; jungler
в фильтр не вынесен. Данные меняются редко, поэтому лежат в `roles.py`, а не
качаются при запуске; обновление — `python tools/update_roles.py`. Тест
проверяет, что у каждого героя из списка и со страницы Dotabuff роли есть:
иначе фильтр молча выкинул бы героя.

**Роль во вкладке «Поиск»** (`counters_with_role`). Короткие таблицы Dotabuff —
по пять строк на всех ролей, после фильтра там почти никого не остаётся,
поэтому разделы строятся из полной таблицы «Matchups»: положительное значение —
«слабее против», отрицательное — «сильнее против». Так списки не пересекаются,
даже если героев с ролью мало. Смена роли перерисовывает последний ответ без
сети. Если полной таблицы на странице нет, выводится предупреждение и все
герои.

**Редкие пары** (`MIN_MATCHES = 2000`, `dotabuff.reliable`). Число матчей
в паре — колонка «Matches Played» полной таблицы (`Matchup.matches`). Замер по
всем 127 героям (сентябрь 2026, 7.41f): медиана 36 701 матч, меньше 2 000 —
0,5% пар, меньше 5 000 — 3,7%. Редкие пары почти все с участием Chen,
Batrider, Elder Titan, Lycan, Visage, Brewmaster; у самого Chen таких 37. При
2 000 матчей погрешность винрейта около ±1,1 п.п., а медиана модуля
преимущества — 0,82: у таких пар цифра — в основном шум. Порог выбрал
пользователь.

- В разделах поиска (`select_sections`, `counters_with_role`) редких пар нет:
  разделы всегда строятся из полной таблицы без них, короткие таблицы
  Dotabuff — только запасной вариант, если полной нет или в ней мало
  надёжных строк. Замер вживую: у Chen из «слабее против» ушли Batrider
  (+6,40 на 663 матчах) и Broodmother (+5,43 на 1 237).
- В драфте (`analyse`) редкая пара даёт **ноль**, а не выбрасывает кандидата:
  кандидат обязан встретиться у всех врагов, и одна редкая пара иначе убрала
  бы героя из подсказок совсем.

### Кеш страниц (`pagecache.py`)

Разобранные страницы лежат в `cache/pages/<slug>.json` рядом с программой, там
же, где иконки. Хранится не HTML (140 КБ), а полная таблица и, если
понадобились, короткие — около 30 КБ на героя, на всех около 4 МБ. Разделы под
любое «КОЛ-ВО» собираются из сохранённого заново (`select_sections`).

- Срок — 24 часа (`MAX_AGE`, выбрал пользователь). Время из будущего — промах:
  часы могли перевести.
- Сохраняется номер патча. Когда программа узнаёт текущий патч, страница
  прошлого патча считается устаревшей. Запасной номер (`FALLBACK_PATCH`,
  когда сеть не ответила) для сверки не используется — иначе при упавшей сети
  программа выбросила бы весь кеш и осталась бы без данных.
- Испорченный файл, другой `FORMAT`, небезопасное имя — просто промах.
  Запись атомарная: во временный файл своего потока, затем `os.replace`.
- `fetch_counters(..., cache=)` берёт кеш, если он передан; тесты передают свой
  во временной папке или не передают вовсе. Кеш общий у поиска, драфта и
  оверлея.
- **Ловушка:** `os.listdir(None)` читает текущую папку. Кеш без папки (её не
  удалось создать) обязан проверять это явно, иначе `clear()` удалил бы все
  `.json` рядом — включая `dota_config.json`. Тест на это есть.

В статусе поиска страница из кеша подписана: «сохранено 3 ч назад». В
настройках — сколько героев сохранено и кнопка «Очистить».

### Подсказки при вводе (`heroes.py`)

Два ключа на каждое имя:

- `_key` — транслитерация и отбрасывание не-букв: `Anti-Mage` → `antimage`,
  `Пудж` → `pudzh`. По нему идёт **точный** поиск (начало строки, затем
  вхождение).
- `_fuzzy_key` — тот же ключ со сглаженным написанием (`ks`→`x`, `ee`→`i`,
  `dzh`→`dj`, схлопывание двойных букв). По нему идёт **нестрогое** сравнение
  через `difflib`, порог `FUZZY_RATIO`.

Нестрогое сравнение включается, **только если буквально ничего не совпало**.
Иначе к точным попаданиям примешивался бы шум: «pud» выдавал бы Hoodwink.
Сглаживание нельзя применять к точному поиску — «ck» перестанет находить
Clockwerk.

Результат на тридцати русских написаниях: 28 первой подсказкой, 30 в пятёрке.

**Прозвища** (`NICKNAMES`): сленг и сокращения, которые транслитерация не
ловит, — «бара», «шейкер», «sf», «карл». Русские и латинские сокращения
записаны отдельно: «вк» транслитерируется в «vk», а не в «wk». Точное прозвище
идёт первой подсказкой, начало прозвища — после начал настоящих имён, чтобы не
вытеснять их: «void» даёт Faceless Void и следом Void Spirit. Тест следит, чтобы
прозвище не принадлежало двум героям и не совпадало с именем другого героя.

**Что уходит на Dotabuff** (`best_match`): точное имя, затем прозвище, затем
первая подсказка. До 1.7 Enter без выбранной подсказки отправлял набранное как
есть, и «пудж» давал «герой не найден», хотя подсказка показывала Pudge.

**Имена героев** должны совпадать с Dotabuff буква в букву: адрес страницы
строится из имени. До 1.7 в списке были «Pango» и «Wind Ranger», а Dotabuff
знает Pangolier и Windranger — поиск этих героев не работал ни разу. Сверка —
с `datafeed/herolist` Valve, имена там те же, что у Dotabuff. Старые имена
остались прозвищами, а недавние и избранное из конфига приводятся к новым при
загрузке.

### Иконки (`icons.py`)

- Память → диск (`cache` рядом с конфигом) → сеть. Иконки не меняются годами,
  а поиск тянет их полтора-два десятка: повторный поиск ускоряется с 1,9 до
  0,3 секунды.
- Все иконки вписываются в одинаковую рамку с прозрачными полями, поэтому
  квадратные иконки способностей и вытянутые иконки предметов выстраиваются
  в ровную колонку.
- Значок таланта есть на CDN только в SVG, а PIL его не читает. Вместо тяжёлой
  зависимости — минимальный растеризатор: `<path>` с командами `M L H V C Z`,
  сплошная заливка, дырки по правилу even-odd. Неизвестная команда → `ValueError`
  и пустое место вместо значка.
- Тонкие контурные значки утолщаются перед уменьшением, иначе на 16 пикселях
  превращаются в серое пятно.
- Одноцветные значки перекрашиваются в цвет текста темы: белый значок Valve
  не виден на светлой теме.
- Значков регенерации здоровья и маны на CDN нет — они рисуются программой.
- Значки Аганима берутся из иконок **предметов**: в `heroes/stats/aghs_*.png`
  лежат блёклые контуры «неактивного» состояния, на тёмной теме невидимые.
- **Ссылки на картинки держит само поле вывода** (`area.icons`, очищается в
  `_clear_area`). `PhotoImage` без ссылки из Python удаляется, и Tk рисует
  пустое место. До 1.8 иконки поиска и драфта лежали в одном списке
  `hero_images`, и перерисовка одной вкладки выбрасывала картинки другой —
  нашёл пользователь.

### Обновления (`updates.py`)

Раз в сутки (дата в конфиге) и по кнопке программа спрашивает у GitHub
последний релиз, сравнивает версию и показывает плашку.

Установка: скачать → **сверить SHA-256 с тем, что публикует GitHub** →
переименовать работающий `.exe` в `.exe.old` → поставить новый на его место →
запустить и выйти. Заменить работающий файл Windows не даёт, а переименовать —
позволяет. `.old` удаляется при следующем запуске. Если переместить не удалось,
резервная копия возвращается назад.

Новая версия запускается с **очищенным окружением** (`relaunch.py`).
Onefile-сборка передаёт потомкам путь к своей папке распаковки через
переменные `_PYI_*`. Унаследовав их, новый `.exe` считает себя потомком
старого и работает из его папки, а выходящая старая версия эту папку удаляет
вместе с сертификатами для HTTPS. Так в 1.5 после обновления не работала сеть
и в шапке висел запасной патч `7.41b` до следующего ручного запуска. Лечится
удалением `_PYI_*` и флагом `PYINSTALLER_RESET_ENVIRONMENT=1`; ещё ставится
метка `DOTACOUNTERS_CLEAN_START=1`.

Перезапуск выполняет код **старой** версии, а 1.5 и более ранние окружение
не чистят. Поэтому новая версия чинит себя сама: `main.py` ещё до tkinter и
сетевой библиотеки проверяет, лежит ли рядом `.old` и нет ли метки чистого
запуска. Если так — её запустила старая версия, и она перезапускает себя
начисто и выходит. Метка не даёт уйти в петлю. Побочный эффект: если `.old`
почему-то не удаляется, каждый ручной запуск делает один лишний
перезапуск — медленнее на секунду-две, но работает.

Имя файла версии не содержит — `DotaCounters.exe`: обновление ставит новый
файл на место старого, и версия в имени быстро переставала бы совпадать с
содержимым.

Установка предлагается, только если это собранный `.exe` и папка доступна на
запись; иначе остаётся ссылка на страницу релиза.

### Оверлей (`ui/overlay.py`, `hotkey.py`)

Узкое окно поверх всех остальных (`-topmost`), без рамки (`overrideredirect`),
с двумя режимами: контрпики одного героя и драфт. Создаётся при первом показе,
дальше только прячется и показывается. Работает, когда Dota запущена в окне или
в окне без рамки; поверх полноэкранного исключительного режима Windows чужие
окна не рисует, и это не обойти.

**Горячая клавиша.** `RegisterHotKey` из user32 в отдельном потоке с циклом
`GetMessage`: `WM_HOTKEY` приходит в очередь того потока, что регистрировал
клавишу. Колбэк переправляется в интерфейс через `root.after`. Если комбинацию
уже заняла другая программа (или второй экземпляр DotaCounters), регистрация
не удаётся, и рядом с кнопкой «ОВЕРЛЕЙ» появляется красная пометка. Строка
клавиши берётся из `overlay_hotkey` в конфиге; её разбор (`parse_hotkey`)
отделён от регистрации и проверяется тестами. Буква без модификатора
запрещена: она перестала бы печататься во всех программах.

Клавиша выбирается в настройках из `HOTKEY_PRESETS` (без Alt+Shift — в Windows
это переключение раскладки). Смена: старая клавиша освобождается и
**дожидается** завершения своего потока (`stop` делает `join`), иначе новая
регистрация той же или соседней комбинации столкнулась бы со старой. Если
новая занята другой программой, возвращается прежняя и об этом пишется под
кнопками.

Клавиша работает в три состояния: спрятан → показать; показан, но фокус у
игры → забрать фокус; в фокусе → спрятать. Кнопка в главном окне фокус не
перехватывает, а просто показывает или прячет.

**Фокус — главная ловушка.** `focus_force` у Tk для окна без рамки фокус из
чужой программы не забирает: оверлей появлялся, а набранное уходило в игру.
Поэтому `winapi.bring_to_front` вызывает `SetForegroundWindow` для рамки окна
(`wm_frame`). Windows разрешает это процессу, которому пришло последнее
нажатие, — после горячей клавиши это мы. На случай отказа есть
`AttachThreadInput` к потоку активного окна.

**Драфт в оверлее** — тот же `DraftBoard`, что и во вкладке (см. «Подбор в
драфте»). Оверлей меняет состав и вызывает `on_draft_change`; главное окно
докачивает страницы и перерисовывает обе стороны. Иконки будущего вывода
прогреваются в фоновом потоке по снимку состава, чтобы вывод не ждал сеть.
«Фишки» героев оверлей переносит сам, по измеренной ширине: поле переносило бы
по пробелу внутри имени. Поиск контрпиков в оверлее ходит своей сессией, тоже
по одному запросу за раз.

**Пересборка при смене темы или языка.** `_build_ui` главного окна уничтожает
всех потомков `root` — окно оверлея среди них, поэтому оно явно исключено;
оверлей пересобирает себя сам (`restyle`) с сохранением режима, врагов и
последнего результата. Если окно всё же уничтожено извне, `_alive()` это
замечает и при следующем показе окно собирается заново.

Место окна сохраняется в `overlay_pos` после перетаскивания. У окна без рамки
нет заголовка, за который его можно вытащить с края экрана, поэтому
`recent.sane_position` требует, чтобы оно целиком помещалось на экране; иначе
окно открывается справа сверху.

## Конфигурация

`dota_config.json` и папка `cache` (иконки и `pages` — страницы Dotabuff)
лежат рядом с программой. В собранном
`.exe` путь считается от самого исполняемого файла: `__file__` в onefile-сборке
указывает во временную папку распаковки, которая удаляется при выходе.

```json
{
  "theme": "cyber",
  "lang": "ru",
  "limit": 5,
  "last_update_check": "2026-09-24",
  "history": ["Pudge"],
  "favourites": ["Lina"],
  "window": "760x860+100+40",
  "overlay_hotkey": "ctrl+shift+d",
  "overlay_pos": "+1540+120"
}
```

Файл правится руками, поэтому всё, что читается из него, проверяется:
списки чистятся `recent.clean_list`, геометрия — `recent.sane_geometry`
(окно не должно открыться за пределами экрана, если монитор отключили), место
оверлея — `recent.sane_position`, клавиша — `hotkey.parse_hotkey` (непонятная
заменяется на `ctrl+shift+d`). `overlay_hotkey` программа сама не пишет — его
добавляют руками, если стандартная комбинация не подходит.

Запись идёт через `config.update_config(**values)`: `save_config` переписывает
файл целиком, и сохранение темы затёрло бы дату проверки обновлений.

```bash
python -m unittest discover -s tests -v
```

На GitHub тесты и `pyflakes` идут на каждый пуш и пулл-реквест
(`.github/workflows/tests.yml`): Windows, как у пользователей, и Python 3.11,
как в сборке. `PYTHONUTF8=1` обязателен: `unittest -v` печатает русские
описания тестов, а вывод в канал на Windows по умолчанию в cp1252.

Важное ограничение: **тесты не ловят поломку сети**. Когда Dotabuff начал
отдавать 403, все тесты оставались зелёными, а программа не работала. Живой
запрос после изменений в сетевом слое обязателен.

Оверлей тестами тоже не покрыт: регистрация клавиши и перехват фокуса
проверяются только вживую. Приём, который работает: отдельный процесс-«игра»
(простое окно Tk с полем ввода) в фокусе, нажатие клавиши через `keybd_event`,
ввод через `SendInput` с юникодом, и проверка, что набранное не попало в
«игру».

Тест в `test_i18n.py` требует, чтобы верхняя запись истории изменений
совпадала с `APP_VERSION`: поднять версию и забыть changelog не выйдет.

## Сборка и выпуск

```bash
python -m pip install pyinstaller
python -m PyInstaller main.spec
```

**Обязательно `python -m`.** Если в системе несколько Python, `pyinstaller`
из PATH может принадлежать другому: так сборка 1.4 получилась на Python 3.14 и
не запускалась там, где Windows старее, чем он требует. Проверить сборку можно
по имени `pythonXYZ.dll` внутри `.exe`.

Сборка всегда называется `DotaCounters.exe`, без номера версии.

Порядок выпуска:

1. поднять `APP_VERSION`, дописать запись в `upd_text` обоих языков;
2. обновить значок версии в README;
3. прогнать тесты, собрать `.exe`, запустить его и проверить вживую;
4. коммит, тег `vX.Y`, `git push origin main vX.Y`;
5. релиз на GitHub: описание и приложенный `.exe`, в описании — SHA-256.

## Известные ограничения

- Данные берутся с **Dotabuff** — стороннего сайта. Перевёрстка страниц или
  ужесточение защиты ломают разбор до выхода обновления.
- Порог редких пар жёсткий: 1 999 матчей — ноль, 2 000 — полная цифра.
  Плавное сжатие к нулю рассматривалось и отложено.
- Прозвища понимаются только те, что есть в словаре `NICKNAMES`.
- Вражеский драфт автоматически не читается. Game State Integration отдаёт
  игроку только его самого и его героя — пики противника видны лишь
  зрителю или тренеру. Так же упираются и другие помощники драфта: врагов
  вводят руками. Остаётся распознавание экрана драфта, но это хрупко и тяжело.
- Оверлей не виден поверх Dota в полноэкранном исключительном режиме — только
  в окне или в окне без рамки.
- Сборка не подписана сертификатом — Windows SmartScreen предупреждает.
- Проект **не связан с Valve Corporation**. Dota 2 — торговая марка Valve.
